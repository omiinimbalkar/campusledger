Student Academic & Activity Ledger

This project records student profiles, prior education, gap years, semester results and campus portfolios. The browser interface uses an Express API backed by a local SQLite database. Google Sheets is an optional one-way export.

Start and operate the app

  1. Install Node.js 18 or newer.
  2. In the project folder run npm install, then npm start.
  3. Open http://localhost:3000. The first launch creates the local database and sample records.
  4. Search by student name or roll number, select a student, and use the profile tabs to view academic progress, seminars and activities.
  5. Use Add/Edit controls to maintain student profiles, education, semester subjects and marks, gap years, seminars and activities. Use Delete for records you intend to remove.

Demo logins: Admin admin / admin123 can search and manage the full roster. Student student / student123 can view the read-only profile linked to roll number CS-2022-014. Both can see education, grades, gap years, seminars and activities for the permitted profile. Sign out to switch roles. These fixed demo credentials are for classroom demonstration only.

The dashboard chart plots SGPA and CGPA by semester and marks gap years. Seminar records are categorized Internal or External. Activities are categorized Technical, Co-curricular or Extracurricular.

Database model and constraints

schema.sql defines separate related tables for students, advisors, education, gap years, semesters, subjects, seminars and activities. Primary and foreign keys prevent orphaned records. Student dependents and semester subjects cascade on deletion; deleting an advisor sets the optional student reference to NULL. Unique constraints prevent duplicate roll numbers/emails, student education levels, semester numbers, subject codes within a semester, and repeated event keys.

CHECK constraints restrict statuses, categories and participation values; constrain years and credits; keep education and subject marks between zero and their configured maximum; and keep SGPA/CGPA between zero and ten. Theory, internal, external, practical and lab marks and maximums are stored on subject rows. Semester and its subjects are inserted as a transaction. SGPA is entered with the semester; CGPA is calculated from the prior CGPA and new SGPA, rather than derived from marks.

The Express API checks values and returns readable client errors before writes. SQLite constraints provide a final integrity check. Duplicate or invalid values are rejected; a failed semester/subject transaction does not leave partial semester data. Student deletion cascades to dependent records.

Google Sheets setup and synchronization

  1. Create a Google Cloud service account, enable the Google Sheets API, and create a spreadsheet with a worksheet named Ledger.
  2. Share the spreadsheet with the service-account email as an editor.
  3. Copy .env.example to .env and set GOOGLE_SHEETS_ID, GOOGLE_SERVICE_ACCOUNT_EMAIL and GOOGLE_PRIVATE_KEY. Keep escaped newlines in the key as \n.
  4. Restart the server. Successful writes through the GUI/API start a one-way snapshot export. The Google Sheets button requests an immediate sync and can retry after a failure.

Spreadsheet edits are not imported. Sync replaces the contents of the Ledger tab with a current snapshot, so put manual notes on another tab. If Sheets is unavailable, SQLite remains saved and the GUI can retry.

Direct database updates

For direct SQL maintenance, stop the server, back up the database file (default data/ledger.db), and edit it with a SQLite client using the schema in schema.sql. Enable foreign keys in that SQL session with PRAGMA foreign_keys = ON and preserve all constraints. Restart the app after editing. Direct SQL bypasses API validation and does not trigger automatic Sheets sync; click the Sheets button to export those edits. Prefer the GUI/API for normal data entry.

What to do next

  1. Sign in as Admin and add or update sample records.
  2. Sign out and sign in as Student. Confirm the student sees their own profile and cannot edit or access another student's record.
  3. If Sheets is configured, sign in as Admin, press the sync button and check the Ledger worksheet.
  4. For a real deployment, replace demo credentials with managed accounts, securely hashed passwords, HTTPS and a stable secret. Decide how direct SQL writes should trigger synchronization.

Coverage note

The app provides the database model, search, progression chart, gap markers, portfolio filters, detailed marks and optional Sheets export. The current implementation uses SQLite. Sheets credentials are optional, direct SQL changes require a manual export, and two-way synchronization is not implemented. Therefore, the guideline requiring mandatory automatic sync for every direct database change is not fully met.

For setup variables and API details, see the project-root files README.md and schema.sql.
